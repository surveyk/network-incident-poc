# Network Incident PoC — Report Specification

## 1. 목적

본 문서는 네트워크 장애분석 PoC가 최종적으로 생성해야 하는 **관리자용 장애 상황보고서의 출력 기준**을 정의한다.

본 PoC의 최종 목적은 장비 로그를 단순히 분석·표시하는 것이 아니라,

**장애 위치 → 업무 영향 → 업무 중요도 → 복구 우선순위 → 복구 상태 → 반복 여부**

를 관리자가 신속하게 판단할 수 있는 형태로 제공하는 것이다.

세부 장비 로그 및 기술 분석정보는 관리자용 요약보고서와 분리한다.

---

# 2. 최종 보고서 구성

최종 보고서는 다음 4개 영역으로 구성한다.

1. 장애 요약
2. 장애경과
3. 조치내용
4. 추정원인 및 추가확인

동일 정보를 여러 영역에서 반복하지 않는다.

---

# 3. 장애 요약

장애 상황을 5W1H 원칙에 따라 정리하되, 보고서에서는 자연스러운 업무용 항목명을 사용한다.

## 출력 항목

| 항목 | 설명 |
|---|---|
| 발생일시 | 장애 최초 감지 ~ 복구시간 |
| 장애구간 | 장애가 발생한 위치 또는 네트워크 구간 |
| 업무영향 | 영향을 받을 가능성이 있는 주요 업무·시스템 |
| 추정원인 | 분석된 주요 장애 원인 후보 |
| 조치결과 | 주요 조치 및 결과 |
| 현재상태 | 장애 지속 / 복구 / 확인 필요 |

별도 핵심 판단정보를 함께 제공한다.

- 업무 중요도
- 복구 우선순위
- 반복 장애 여부

## 출력 예시

| 구분 | 내용 |
|---|---|
| 발생일시 | 2026. 9. 30. 10:21 ~ 10:22 |
| 장애구간 | **2층 네트워크 구간** |
| 업무영향 | **112시스템**, 온나라, 폴넷 |
| 추정원인 | **2층 내부 네트워크 Loop 가능성** |
| 조치결과 | 이상 포트 차단 후 네트워크 정상화 |
| 현재상태 | **복구 완료** |

**업무 중요도: 매우 높음 / 복구 우선순위: 최우선 / 반복 장애 여부: 확인 필요**

---

# 4. 장애경과

관리자가 장애 흐름을 쉽게 이해할 수 있도록 핵심 이벤트만 시간순으로 제공한다.

전체 원본 로그를 표시하지 않는다.

기본적으로 다음 단계를 표현한다.

**이상징후 → 장애발생 → 조치 → 복구**

## 출력 예시

| 시각 | 장애경과 |
|---|---|
| 10:21:02 | MAC 주소 반복 이동 등 이상징후 최초 감지 |
| 10:21:22 | Broadcast 트래픽 증가 |
| 10:21:24 | **2층 네트워크 연결 중단** |
| 10:22:05 | 장애 의심 포트 차단 |
| 10:22:13 | **2층 네트워크 연결 복구** |

관리자용 보고서에는 원칙적으로 4~6개 핵심 이벤트만 표시한다.

세부 이벤트는 상세 기술분석에서 제공한다.

---

# 5. 조치내용

실제로 수행된 조치만 기록한다.

향후 수행해야 할 확인사항과 혼합하지 않는다.

## 출력 예시

- 장애 의심 포트 차단
- 2층 네트워크 연결상태 정상화 확인
- Broadcast 및 장비 상태 정상화 확인

---

# 6. 추정원인

장비 로그에서 확인된 사실을 근거로 주요 원인 후보를 간략하게 설명한다.

AI 분석 결과는 확정 원인이 아닌 **추정 결과**로 표시한다.

## 출력 예시

장애 전 **MAC 주소 반복 이동과 Broadcast 증가**가 확인되었으며, 장애 의심 포트 차단 이후 네트워크가 정상화된 점을 고려할 때 **2층 내부 네트워크 Loop 가능성이 높은 것으로 추정된다.**

장비 로그만으로 실제 케이블 연결상태 및 하위 장비 구성을 확인할 수 없으므로 현장 구성 확인 후 최종 원인을 판단한다.

---

# 7. 추가확인

복구 이후 담당자가 추가로 확인해야 할 항목을 별도로 표시한다.

## 기본 항목

- 주요 업무서비스 정상 여부
- 동일 구간의 과거 장애이력
- 동일 유형 장애 반복 여부
- 추정 원인의 현장 확인 필요사항

## 2층 Loop 장애 예시

- 112시스템 정상 여부
- 온나라·폴넷 정상 여부
- 동일 포트 또는 2층 장애이력
- Loop 의심 포트 실제 연결상태

---

# 8. 기술 상세정보

다음 정보는 관리자용 본문에 반복해서 표시하지 않는다.

- 전체 원본 로그
- 전체 이벤트 Timeline
- CPU 세부 수치
- Broadcast 세부 수치
- MAC Address 상세정보
- 포트별 기술정보
- AI 추론 전체 근거

해당 정보는 Web의 상세보기 또는 별첨 기술분석에서 제공한다.

---

# 9. 출력 원칙

최종 보고서는 다음 원칙을 따른다.

1. 첫 화면에서 장애 위치와 업무영향을 바로 확인할 수 있어야 한다.
2. 업무 중요도와 복구 우선순위를 명확히 표시한다.
3. 현재 복구상태를 명확하게 표시한다.
4. 반복 장애 여부를 표시한다.
5. 동일한 내용을 여러 영역에서 반복하지 않는다.
6. 기술용어는 필요한 경우 쉬운 명칭으로 변환한다.
7. 로그 기반 사실과 AI 추정을 구분한다.
8. AI가 최종 장애원인을 확정하지 않는다.
9. 최종 판단은 담당자가 수행한다.
10. 관리자용 보고서는 1페이지 수준을 목표로 한다.

---

# 10. PoC 성공 기준

2층 Loop Golden Sample을 입력했을 때 최소한 다음 결과가 생성되어야 한다.

- 장애구간: `2층 네트워크`
- 영향업무: `112시스템`, `온나라`, `폴넷`
- 업무 중요도: `매우 높음`
- 복구 우선순위: `최우선`
- 현재상태: `복구 완료`
- 주요 원인 후보: `L2 Loop`
- 반복 장애 여부: `확인 필요`
- 핵심 장애경과 자동 생성
- 관리자용 장애 상황보고 자동 생성
